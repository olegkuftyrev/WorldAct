# Bounded email message parser foundation

`parseMailMessage` decodes a retrieved message into body, HTML/plain mode, subject, ordered sender candidates and an optional date. It does not grant sender identity or publishing rights, sanitize body HTML for storage, connect to a service, create a post, or delete mail. Those operations belong to the separate owner documented in `mail-intake.md`.

References: supplied `wp-mail.php` and MIME [RFC 2045](https://www.rfc-editor.org/rfc/rfc2045), [RFC 2047](https://www.rfc-editor.org/rfc/rfc2047). Supported messages are text/plain, text/html and bounded multipart/alternative, with strict base64, quoted-printable or unencoded byte transfer. The HTML alternative is preferred; plain text remains the fallback. Subject encoded words and declared body charsets decode locally. Folded headers are unfolded; duplicate identity/format headers are rejected. From/Reply-To accepts a strict single bare or display-name/angle mailbox. Display/comment text is never searched for email substrings; ambiguous or unsupported address syntax produces no candidate. Actual author/capability lookup remains mandatory.

The parser caps raw bytes at 1 MiB, headers at 32 KiB/100 fields, MIME nodes at 16, nesting at four levels, alternatives at eight per multipart, parameters at 16 and decoded aggregate bytes at 1 MiB. Encoded subject work has independent length/word limits. Invalid encodings, NUL text, unsupported charsets, MIME attachment/file parts and other multipart types fail with a fixed safe code. Filename/name parameters include extended and numbered continuation forms; malformed disposition parameters also fail. Unsupported mail must remain in the mailbox; the intake owner must not delete it or claim its attachments were imported. No remote image, resource or attachment is fetched.

The source subject prefix before `::` is decoded here. The intake service applies the source `::` body and XML-RPC-style title conventions, ordinary storage sanitization, category/author/status/date decisions and receipt idempotence.

Seven meaningful guarded parser checks pass, including real non-ASCII B/Q encoded words, folded headers, UTF-8/Latin-1 body bytes, alternate-body selection, safe unsupported failures, malformed/duplicate headers, false sender identities, bad transfer data/boundaries and independent resource bounds. Together with the POP transport, fifteen checks pass without network or mailbox credentials. This checkpoint is not a completed Post via email feature.

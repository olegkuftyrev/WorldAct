# Incoming ping notifications and typed comments

This Node/PostgreSQL implementation ports the supplied WordPress7.1.4 source behavior without executing PHP. Reference: `class-wp-xmlrpc-server.php:6974–7223` (`pingback_ping`), `wp-trackback.php:18–211`, `comment.php:752–984,2315–2322,2372` (duplicate/flood/admission) and `3885–3917` (old normal-post closure), the REST comments controller collection/type checks, `default-filters.php` and the independent outgoing publication hooks.

## Working receiver contract

- `POST /xmlrpc.php` accepts only `pingback.ping`, exactly two XML-RPC string arguments: source and target URLs. It returns a real XML-RPC string success or generic fault. Unknown methods, publishing and multicall are unsupported. `getPingbacks` is not advertised or implemented.
- `POST /wp-trackback.php?tb_id=ID`, `/wp-trackback.php/ID`, and canonical `.../trackback/` accept the fixed `url`, `title`, `excerpt`, `blog_name`, optional `charset` form fields. Success is `<response><error>0</error></response>`; failure is the source XML error shape. Trackbacks are **unverified claimed notifications**; their URL is never fetched and never supplies an account or approval exception.
- Parsers mount before generic JSON and authentication. These endpoints always act anonymously, regardless of cookies or Authorization, and accept legitimate server-to-server requests without weakening Origin checks on `/api`, native forms, sessions or application passwords.
- Both protocols operate only when the reviewed ping environment is `production`. Main/local/development/staging reject before DNS or HTTP. Production is the source's genuinely-unset environment default; setup and isolated testing explicitly use local. There is no public private-network or environment override.

## Public target and source checks

Target resolution is exact against the configured site's origin and supported canonical permalink. It selects metadata only, not content, password hashes or cookies. It requires a published normal post/page, no password protection, and `pingStatus: open`. `closeCommentsDays` closes old **normal posts only**, never pages. Canonical changes and settings/environment are rechecked in the final transaction. Expired or removed admission leases cannot commit a late verification.

A pingback uses the existing reviewed public-only HTTP transport, fixed GET, redirects0, no credentials/cookies/forwarded IP, wire/decoded150KiB, its existing8second request/DNS/socket deadlines and peer pinning. Every DNS answer and actual peer must be public; the HTTP adapter retains physical reservations through socket closure. The receiver additionally waits for physical closure before returning its verification reservation. Inert HTML parsing is bounded10000nodes/depth80, requires a real nonempty title and an actual resolved `<a href>` to the normalized exact target. Script/style/template/SVG/Math/iframe/object/noscript text cannot fabricate backlinks. Stored context is escaped and bounded.

Own-origin sources (including the configured application origin) are deliberately unsupported. No localhost exception, recursive rendering, claimed local-author shortcut or private-page resolver exists. Protected targets are rejected even if a caller sends a valid password cookie. This is an explicit stricter public-only adaptation of the source. The optional Trackback charset field accepts UTF-8/ASCII; unsupported labels, including UTF-7, are rejected rather than guessed.

## Storage, moderation and lifecycle

`comments.type` is constrained `comment|pingback|trackback`, with default `comment`; migration preserves all existing records. A trigger always clears email/account identity on typed pings and computes a bounded SHA-256 source key. A partial unique index on post/key prevents concurrent typed duplicates, including pingback versus trackback. Receiving also checks an existing human comment with the same source URL, matching the source duplicate rule. URL normalization removes fragments and credentials are rejected. Imports normalize typed URLs, allocate fresh post/comment IDs, rebuild identities and reject duplicate source/target data atomically rather than silently dropping it. Old JSON/WXR comments remain normal comments; new archives preserve the type. Nothing sends notification events when imported.

After successful source verification (or bounded trackback parsing), a short metadata-only transaction takes the shared comment hierarchy lock and checks duplicate source identity before the existing ordinary flood helper. Notifications remain anonymous: the newest comment in the previous hour matching empty email **or** actual request IP participates globally across posts, types and statuses. An administrator cookie or claimed identity never supplies the moderator exemption. UTC integer-second differences below15 reject; exactly15 permits. This early check avoids moderation and Akismet for an already known flood and releases its PostgreSQL client before that processing.

The final transaction repeats duplicate → live lease → flood admission after its real hierarchy, post and settings waits and current target/configuration checks. It samples one PostgreSQL wall-clock second for the authoritative flood comparison, initial creation/update times and one-hour metadata expiry. This final check is necessary because another human or ping may commit while verification or Akismet is in flight. Distinct concurrent notifications cannot both pass the shared admission lock; same-source races retain duplicate fault48 precedence. A flood becomes the existing generic XML-RPC fault0 / Trackback error1, including direct-service `IncomingPingError(0)`, without exposing an internal429, private IP or ordinary comment error message. Rejected admissions insert no comment, retained per-comment IP/Akismet record or notification mail; their live lease is removed. Earlier attempt buckets remain consumed. An external filter already in flight cannot be undone, including its existing connector-health update; no external I/O is performed while holding an admission client. No new schema, retention or rate override is introduced.

The extracted `comment-policy.ts` applies ordinary disallowed keys→Trash, moderation keys, link limit, explicit moderation and the active local spam classifier to pings. A ping's empty email/claimed URL never inherits previous-human approval or trusted authenticated-human authority. Human prior approval uses actual account history or matching guest name/email; an authenticated current post author/global moderator receives source approval before ordinary policy, while plugins remain filters. See [human approval identity and lock order](comment-policy.md). Active verified Akismet receives the actual constrained `comment_type`; its verdict and retained submission metadata use the existing comment lifecycle. No service is contacted in tests. Public submission and REST creation cannot forge ping types. Moderators can edit a ping under existing ownership/role/version rules; its type is immutable, and its email/account remain empty. The same transactional notifications are queued locally and delivered only after commit/release.

Persistent admission buckets allow30 accepted attempts/IP/hour,10/source/hour,100/target/hour and300 globally/hour; keys store hashes, not request IP text. Old-hour buckets are removed; the global300 cap bounds the current-hour key set to at most901 hashed keys. A process cap of16 covers requests waiting for database admission, before any pool query. Short advisory-locked admission transactions allocate at most2 live verification leases, expiring120seconds for process-crash recovery. Each lease is removed only after actual verification settles; expiration fails closed, with the exact lease checked under lock before insertion and again immediately before commit. the shared transport independently caps live sockets. No PostgreSQL client is held during source verification or Akismet I/O. Final insert uses comment hierarchy → post SHARE → settings SHARE, rechecks current configuration/target, then checks duplicate, live lease and ordinary flood before inserting uniquely and queuing mail. Failures roll back; generic responses do not echo remote bodies, diagnostics, private metadata or credentials. No raw remote HTML is retained.

## Defaults, collections and public behavior

Administrator settings add `defaultPingStatus: open|closed` (source defaultopen), independent of outgoing `defaultPingbackFlag`. Discussion presents the three source default checkboxes in order, with the shared new-post-only description. New normal post creation without an explicit flag uses it; pages defaultclosed. Fresh once-only Hello world content uses the setting. Existing per-post flags are never rewritten. Safe site archives include this ordinary site setting; destination-local outgoing URLs/configuration remain excluded as before.

`GET /api/comments` adds optional `type=all|comment|pingback|trackback`, defaultall for the existing admin list; counts retain the selected type scope and existing permission/privacy behavior. Every comment DTO includes `type`. Native REST `/wp-json/wp/v2/comments` defaults to `type=comment` and approved status (including edit context), as source; authorized content roles can filter pingback/trackback or empty type for all public approved types. Existing edit-context moderation permissions remain. A mutation may repeat the unchanged type, but cannot convert it. Normal public comment submissions remain human-only. Stored ping text remains raw safe source content; public/REST/theme display applies the installed source paragraph formatter without changing normal human-comment rendering. Mixed public comment counts include approved pings; theme output carries the type and omits ping reply controls. Private email/retained Akismet metadata never enter public DTOs.

`X-Pingback` is emitted only in production for singular public unprotected content currently allowing pings, including actual served document paths, public post API and public template responses. Archives, previews, closed/private/protected targets and local environments do not advertise a receiver. The Vite proxy includes both fixed endpoint prefixes for development parity; local receiving still rejects by environment.

## Boundaries

Admin Comments provides source All comment types / Comments / Pings filtering, grouping pingback and trackback. Available type counts follow readable-post scope independently of status/search/page; committing a type filter resets the selection and editor while retaining the type through navigation and moderation. Typed rows and edit forms show their fixed notification type without email/account identity. Existing moderator Reply permissions remain authoritative, while source and legacy public trees omit Reply on notifications. Empty Spam/Trash continues its existing all-type scope and states that scope in the review dialog.

No authenticated XML-RPC publishing, multicall, own-site verification, arbitrary provider callbacks, outgoing explicit trackbacks or charset auto-detection. Capacity/leases recover crashes, but a concurrent retraction cannot undo a verification request already in flight; final state is always checked before storage. Legacy unknown comment types outside the supported constrained model remain outside this batch. Configured mailbox intake is documented separately in `mail-intake.md`.

## Flood regression scope

`incoming-ping-flood.test.ts` uses actual XML-RPC/Trackback HTTP, PostgreSQL history and lock waits, plus actual human API requests in both directions. Its bounded verification/Akismet adapters are source imports even when the guarded main HTTP server is compiled; those helper calls are not represented as compiled-byte execution. `incoming-ping-flood-production.test.ts` additionally launches the selected real source/compiled production entry and submits actual trackbacks without remote verification or external delivery. Other cases check direct error identity, actual filter-held races, final duplicate precedence, and lease expiry after a real post wait. The permanent compiled CI selector includes both files. Unrelated legacy protocol/moderation fixtures explicitly age only their owned predecessors; immediate duplicates, concurrent requests and flood checks remain unaged. Frozen before/after receipts and exact observed counts are in the scoped implementation evidence.

# Imported singular body-page links

Site archive import now remaps a known pretty body-page URL such as
`/clock/2025/01/01/00/00/39/4/story/2/?query-4-page=3#keep` to the actual imported
post's destination canonical and body page. The destination can use another
pretty structure, a slashless Numeric structure, or Plain query IDs. Independent
query parameters and fragments survive; the destination's body-page counter is
generated by the existing content-page URL helper.

The body-page metadata is separate from the general URL map, which also contains
terms, uploads and fonts. The portability finalizer adds it only for a known
exported normal post/page with `publish` status, a published imported target, an
explicit non-root pretty source permalink, and more than one page in the copied,
sanitized source body. The page count uses the existing content marker parser;
inert escaped markers do not add pages. The metadata stays local to that import
instance and uses its transaction's actual destination post/canonical/settings.

Resolution order is deliberate:

1. Exact canonical identities across the complete mixed map win, regardless of
   iteration order. Existing complete query/hash URL continuations are also
   considered before any body suffix.
2. A known canonical numeric child such as `/parent/2/` therefore stays that child,
   even when its parent also has two body pages. An alternate trailing slash of a
   known child is left unchanged rather than interpreted as its parent's page.
3. Only a single literal positive numeric suffix, from 2 through the copied
   source body count and no greater than 2147483647, can use explicit body-page
   metadata. No leading zeros, encoded separators, extra subpaths, or arbitrary
   prefix guesses are accepted.
4. Apply one mapping. A generated destination URL is never fed back through the
   source map. If another entity shadowed the same canonical mapping, conflicting
   body metadata cannot override it.

Relative and absolute source URLs have separate exact map entries. A matching
path inside an unrelated origin or another URL's query does not authorize a
rewrite. The existing whole-URL content scanner is unchanged. Raw and JSON block
references, copied design/entity content, and legacy menu URLs share the mapper.
Term/media/font numeric lookalikes remain unchanged while their ordinary
canonical links still remap.

When a destination already has a Plain query identity, an independent source
`?query` is joined with `&`, avoiding a second question mark. A query that would
introduce another fixed identity or duplicate the already-selected Plain body
page is left unchanged. Existing source Plain fixed-ID prefix boundaries and
query continuations remain intact; this batch does not add source-Plain-to-Pretty
body-page conversion semantics.

This change does not alter publication/type/fixed-ID/password fences, body-page
clamping or HTTP/canonical redirect policy. Source private/draft/future records,
and password-protected records imported as drafts, do not authorize the new body
suffix mapping. Existing root/static-front body paths and source records without
an exported canonical are outside this new metadata contract.

Archives describe an exported entity graph, not a full source resolver history.
If an **omitted** source numeric child shares a valid parent body-page spelling,
the archive cannot prove which source entity that original link resolved to.
The mapper can preserve the known imported child identities, but no complete
ambiguity guarantee is claimed for absent identities. Those indistinguishable
links must not be described as provably untouched. A source identity manifest
would be a separate archive-format change.

The original failing fresh-archive probe is preserved separately from the token
draft. It now passes unchanged on source and compiled restores. Permanent checks
cover actual fresh IDs, Plain/Numeric/custom destinations, query/hash and absolute
menu links, real numeric children, ordinary versus numeric term/media links,
protected/private denial, inert escaped text, and a late import failure that
rolls back rows/settings/uploads followed by a successful fresh-ID retry.

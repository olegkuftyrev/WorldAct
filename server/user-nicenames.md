# Persisted public author identities

`users.nicename` is a stable, unique, non-null `varchar(50)`. New accounts use the supplied WordPress source's default rules within WorldAct's existing ASCII username contract: take the first 50 characters, lowercase, replace periods with hyphens, remove `@`, preserve underscores, collapse hyphens and trim outer hyphens. Empty results and the PHP-empty literal `0` are rejected. `_` and `000` remain valid. Collisions take the first available `-2`, `-3`, and later suffix, shortening the original base to `49 - digits(suffix)` characters without sanitizing the assembled result again. An interior doubled hyphen at that boundary is valid.

Profile display names, email, passwords, roles and subsequent username storage changes do not rename an assigned identity. There is no nicename editing API, database trigger or public lazy repair. Each of the administrator, registration, browser installation and CLI seed creation paths allocates explicitly in its transaction; the database independently enforces shape, width and uniqueness.

The additive migration reserves all valid existing assigned identities, then fills only null identities in ascending ID order. Historical usernames outside the existing supported ASCII creation contract, or whose default result is empty/`0`, get deterministic `user-ID` fallback identities with the same collision rule. Their original username and all other columns remain unchanged. This preservation fallback does not claim that WordPress creates these invalid historical logins. Invalid or duplicate non-null identities fail the entire migration atomically. Repeated migrations keep assigned identities stable.

## Transaction order and deployment

Stop old application writers before applying this migration and restart on the coordinated code. Mixed old/new writer deployment is unsupported: old inserts do not supply the required identity. The creation barrier is not a general online schema migration guarantee for unrelated application-password, privacy or settings operations.

Migration takes `worldact-migration`, then `worldact-user-creation`, then existing `users ACCESS EXCLUSIVE` as its first application relation lock. It does not acquire account identity. Ordinary account creators take the creation barrier immediately after `BEGIN`. Administrator creation then locks its actual actor row, checks the current administrator role, takes `worldact-account-identity` and rechecks the actual session/application password after that wait. Registration reads current settings after the barrier. Seed and installation retain their initial seed lock, then take creation and identity locks; seed locks/re-reads any chosen existing administrator before identity so initial-content foreign keys cannot invert a profile's row-before-identity order. Profile mutations keep their established user-row-before-identity order and do not acquire the creation barrier.

Actual bounded PostgreSQL lock observations cover both profile/migration start orders, waiting registration without application relation/identity locks, existing-admin seed without an initial-content marker, credential revocation at both creator waits and live role/settings changes. These schedules completed without `40P01`; they do not prove all possible live DDL schedules.

## Permalink and REST boundaries

`%author%` must occupy a complete path segment, occur once, and accompany `%postname%` or `%post_id%`. It is not itself a post identity. The shared ten-token inventory supplies settings help, validation, generation and resolver captures. Normal pretty-post URLs obtain the author solely through the current persisted `posts.author_id` join and the supplied database client. Missing/stale/incorrect DTO author fields cannot choose the URL. Pages, static front pages, Plain identities and numeric author archive links keep their existing behavior; pretty author archives are not implemented.

Public metadata retains current publication/type predicates during the additional author read. Public body responses using author structures also recheck current publication/type/password and the current request grant after the new lookup wait. Final locked state governs content, comments and the internal raw model. Password unlock uses its newly persisted grant for this check, rather than a trusted boolean. Authenticated previews retain their editor policy. These checks prevent newly read data from crossing the demonstrated wait; already delivered bytes cannot be revoked retroactively. Native user/me, public user records and embedded post/media authors expose the same persisted slug without adding credentials to public metadata.

Archives do not import accounts. Imported post links use the actual destination importing administrator and destination nicename, under the destination's active settings and transaction. Known canonical mappings still precede valid known body suffixes, including real numeric child pages, Plain joins, punctuation, query/hash and rollback behavior. The exported-graph limit remains: an omitted source child can share a valid parent body-page spelling, and the archive cannot prove which original entity that link resolved to. This does not establish a complete ambiguity guarantee.

Historical publication dates continue using the existing chosen-instant/current-site-clock contract. Persisted civil dates and timezone-change fidelity, explicit nicename editing, imported accounts, pretty author archives and canonical redirects are separate work.

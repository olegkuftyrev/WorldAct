# Outgoing publication notifications

This is a Node/PostgreSQL port of the supplied WordPress7.1.4 publication behavior. Reference source is data only; no PHP executes. Source anchors: `wp-includes/post.php:8228–8257` (`_publish_post_hook`), `comment.php:3184–3410,3436–3502,3514–3630,3690–3705`, `default-filters.php:424–433,447`, `wp-admin/options-writing.php:207–245`, `options-discussion.php:50–59` and `includes/schema.php:426–455`.

## Real behavior and configuration

Administrator `/api/settings` accepts:

- `defaultPingbackFlag`: boolean, source defaulttrue. This is outgoing discovery, independent of the existing per-post receiving `pingStatus` metadata.
- `pingServices`: at most20 unique absolute HTTP(S) URLs, source default `https://rpc.pingomatic.com/`. Port80/443/8080 only, no URL credentials, unsafe host literals or control characters. Fragments are removed. DNS/peer validation happens again at dispatch, including all DNS answers. Query strings may be operator configuration: these settings are omitted from public-site and JSON archives, and imported notification settings are ignored with a warning. They are never returned in status or logged.

`WORLDACT_ENVIRONMENT_TYPE` accepts `local`, `development`, `staging`, `production`. Genuinely unset means production, as in the supplied source. Invalid explicit values fail closed as local. `.env.example` and setup use local for this personal study; setup adds local only when no explicit environment line exists. The disposable runner always overrides inherited values to local, as it forces email outbox mode. **Only production dispatches.** Local/development/staging create suppressed outcomes without DNS/HTTP; startup invalidates/drains prior pending/running production leases once. Operators must use the same environment across processes sharing a database.

Normal post creation, each published save (including published→published), bulk/restore saves through the same core path, and scheduled publication enqueue in the same transaction as content changes. A queue failure rolls back the content change. Pages, drafts, private posts and future posts before their due transition enqueue nothing. JSON/WXR direct import paths do not invoke publication hooks. Delivery source URLs use the publication timestamp (or legacy creation timestamp fallback), configured timezone and canonical category/permalink rules. New links on later saves are discovered; successfully sent target hashes are retained per post to suppress duplicate notifications. Deleted posts cascade their per-post jobs/sent hashes. Site-level coalesced service jobs are independent of any one contributing post, and recheck that a published normal post still exists; deleting the newest post cannot erase notification of another publication. Existing post flags/content are untouched.

Update Services obey the separate search-visibility setting and current configured service list. They send the site title/home/feed URL only, first `weblogUpdates.extendedPing(title,home,rss2)` and on failed query `weblogUpdates.ping(title,home)`. The source default can be replaced with an empty list.

## Queue and ownership

`outgoing_ping_jobs` stores discovery, pingback and service work. Discovery coalesces by post; service notifications coalesce by normalized service URL; target notifications coalesce by post/URL hash. A fresh publication increments generation and resets its retry budget, even when a prior generation is leased. Pending/running backlog is capped5000; terminal history is pruned to10000/30days. Queue exhaustion fails the content transaction with a generic503 instead of silently dropping its event. `outgoing_ping_sent` retains durable post/target hashes independently of terminal-history pruning.

The singleton worker claims at most2 rows using a materialized, bounded `FOR UPDATE SKIP LOCKED` candidate set, a random lease token and90second lease. The materialization fence prevents the UPDATE plan from reevaluating its candidate LIMIT. A short claim advisory lock counts unexpired running leases, enforcing the two dispatch slots across processes as well as overlapping ticks. It commits/releases the claim client, then performs I/O. No pooled transaction connection is retained for discovery HTTP or delivery. Discovery inserts target jobs in a separate short transaction, taking the source post KEY SHARE before the queue advisory lock, matching publication's post→queue order. Finalization is guarded by lease token and generation; stale completions cannot overwrite a new owner, while a new publication racing completion is left pending. Expired leases are reclaimable;3 total attempts per generation, backoff60/120/240seconds, then failed. Transient errors use only a fixed safe outcome. Periodic cleanup retains sent hashes.

Remote success can precede a process crash or lease loss. Delivery is **at least once**, not exactly once; remote pingback duplicate fault48 counts as success. Shutdown stops new polling; interrupted work recovers via leases. There is no public dispatch/test bypass or arbitrary RPC registry. Generic GET never delivers.

Administrator `GET /api/tools/outgoing-pings` returns environment/dispatchEnabled, state counts and the100 most recently updated jobs: id, kind, postId, state, fixed outcome, attempts, updatedAt. It exposes no target URLs/queries, payload, lease token, source body, remote response or credential. Resaving a published post is the source-equivalent way to request fresh discovery after a terminal failure; automatic retry remains bounded. There is no receiving endpoint or claim that receiving ping flags work.

## Protocol and resource boundaries

`public-http.ts` is the neutral transport shared by the existing RSS compatibility wrapper and ping protocols. RSS retains GET, its wire1MiB/decoded2MiB limits,3 redirects and existing error contract. Pings use a separate2-connection physical capacity; RSS4. Both share OS DNS limit4; an OS lookup retains its DNS slot until actual settlement. Request capacity is held until actual socket close (not logical abort or request completion); redirects wait for physical closure before starting another hop. Queue waiters are capped64 and share the request deadline. A timed-out socket that has not closed cannot be replaced with another live socket beyond the cap.

All hops use public unicast addresses only, validate every DNS answer (max64), pin the chosen address into Node's lookup callback, compare the actual peer and preserve HTTPS hostname/certificate validation. IPv4-mapped/transitional/reserved/private destinations, local/internal names, credentials, unsafe ports/protocols and redirects are rejected. No caller-supplied headers, Authorization or cookies. Agent reuse/autoselection are disabled. Headers16KiB; wire/body bounds checked during read and decompression. Overall request8seconds, DNS2seconds, socket inactivity4seconds. Internally injectable resolver/request/protocol boundaries support local mocks only; no API/environment transport override exists.

Pingback discovery uses HEAD `X-Pingback` before GET `<link rel=pingback>`, rejects binary resource discovery, bounds HTML150KiB/10000nodes/depth80 and revalidates the discovered endpoint independently. HEAD does not decompress a nonexistent body even if representation headers describe gzip. At most100 unique stored URL tokens per post; excess fails safely. Bare home links, source self links and local uploads are ignored. Each fixed XML-RPC POST has an8KiB request cap, no redirects and64KiB wire/decoded reply cap. Replies use inert UTF-8 XML validation with no DTD/entity declarations, depth12/nodes128. Remote fault text is never persisted. Only `pingback.ping`, `weblogUpdates.extendedPing` and `weblogUpdates.ping` can be generated.

## Explicit remaining boundaries

- No incoming pingback/trackback, explicit outgoing trackbacks, enclosure discovery, mailbox intake, AI provider or Connectors implementation in this batch.
- Incoming follow-up contract: administrator `defaultPingStatus: open|closed` with fresh source defaultopen, applied only to newly created normal posts; pages defaultclosed and existing per-post flags are preserved. Add the typed comment model, working receiving endpoints and old-post ping closure before exposing functional receiving controls or X-Pingback advertising. This outgoing batch deliberately retains the existing closed metadata defaults.
- Stricter protected-content boundary than the source: password-protected posts never have their stored URLs discovered or sent as pingback targets, even for an authenticated operator or cookie grant. Site-level Update Services can still notify with public site metadata; no protected body/excerpt is selected or forwarded.
- Own-site pings are deliberately skipped. There is no localhost HTTP exception or internal recursive render. Supporting verified local ping comments later needs its own fixed public-only SQL resolver and typed comment model.
- Network work rechecks current settings/publication immediately before dispatch, but no database locks are held during a remote operation. A concurrent retraction cannot undo an already-started remote request. Only source permalink/target and public site metadata are transmitted; never a body, password, private account data or request credentials.
- Notification configuration/job history is intentionally destination-local and not a site archive replay instruction. Existing RSS behavior/cache and all unrelated settings/archives remain intact.

Tests use mandatory guarded disposable databases and injected DNS/HTTP/protocol fixtures; no real Internet service, public DNS or SMTP is contacted.

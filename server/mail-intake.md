# Configured Post via email backend

The supplied `wp-mail.php`, `class-pop3.php`, Writing settings, and `xmlrpc_getposttitle` are reference data. The implementation is Node/TypeScript with PostgreSQL; it executes no PHP or MySQL. Browser Writing configuration is a separate pending UI batch.

## Administrator contract

`GET /api/tools/mail-intake` returns actual destination-local configuration/status, never password bytes. `PUT` accepts bounded partial host/username/port/secure/categoryId/enabled/polling settings, a write-only password, explicit clearPassword and an optional version UUID. Blank password retains the existing credential; clearing requires disabling configured checks. A stale version fails409. Read/status and saves do not connect to a mailbox. Only administrators can configure/check, and mutations recheck the live role and session/application password after account locks.

`POST /api/tools/mail-intake/check` accepts only `{}` and checks the saved mailbox. There is no arbitrary per-request endpoint, command, credential or test-transport bypass. Default configuration is disabled with automatic polling off. Administrators can explicitly enable checks and separately opt into the one-minute worker; automatic checks operate only in production. Manual authenticated checks remain explicit in local/development/staging. A persistent five-minute interval and single90second renewable lease coordinate all processes; one process admits only one check before mailbox pool queries. Status reports actual environment/polling suppression and the next allowed check.

The private configuration table and receipts are excluded from site/public/archive models. A mailbox identity hashes normalized host/port/security/username; a credential rotation keeps that identity. Receipts contain only mailbox/UIDL hashes, optional post FK and creation time. Deleting a post sets its receipt post_id toNULL without allowing the same message to resurrect it. Receipts are not pruned; the bounded100000 receipt limit fails closed before another post. A hashed rotating cursor prevents permanently unsupported messages at the front of a mailbox from starving later valid messages.

## Retrieval, storage and deletion

The reviewed fixed POP transport supports explicit plaintext110 or certificate-verified implicit TLS995, public DNS/peer pinning, no credentials before peer/TLS checks, USER/PASS/UIDL/LIST/RETR/DELE/QUIT only, and physical socket ownership through closure. See `pop3.md` for wire/DNS/message bounds. A check examines at most20 listed messages and retrieves at most6MiB of declared payload within the transport's8MiB wire/session bound. Oversized or unsupported messages remain in the mailbox. MIME decoding is bounded and attachment/file parts are explicitly unsupported; see `mail-message.md`. Nothing fetches embedded resources.

Parsed From/Reply-To addresses are claimed identities, never session authentication. Under sorted account locks the service selects the first matching actual account in header order. Current administrator/editor/author capability permits publication; contributor/subscriber is pending with its actual author ID. Unknown senders use an available current administrator as author and remain pending. Display/comment text cannot impersonate an address. The private core wrapper fixes new post type/status and uses an unexported Symbol solely for the pending lower-role author exception; public post mutation validation is unchanged.

Source subject-before`::`, body-after`::`, embedded`<title>` fallback, decoded message date, configured/fallback category and future publisher scheduling feed the ordinary post schema, sanitizer, canonical content, slug allocation, terms, defaults and outgoing publication outbox. Plain text is escaped before the HTML cleaner. No admin identity is fabricated and no direct post SQL bypasses core storage.

No pool client remains held during POP, MIME parsing or remote deletion. Import locks possible authors/operator in ascending order, then mailbox state, and rechecks current authentication, exact generation/lease and wall time. Category IDs are source-style options without a foreign-key callback into mailbox locking; deleted categories fall back through ordinary core selection. Post and unique receipt commit atomically. Only after that commit does DELE run; only successful QUIT reports deletionCommitted. Failed deletion/QUIT is retryable through the durable receipt without making another post. Original UIDL strings, mailbox bodies and passwords are never stored in status/receipts or logged.

The lease renews using separate short pool queries and cannot revive an expired token. Admission/renewal remain owned through actual socket closure, including a failed opening. Long post-lock waits recheck lease/session wall-clock expiry immediately before commit. A changed mailbox generation or revoked operator cannot commit a stale message; an already-issued remote command cannot be recalled.

## Verification and boundaries

Meaningful isolated checks cover actual administrator API/secret privacy, stale configuration, capability/sender order, sanitation/category/date, commit-before-DELE, failed QUIT/deleted-post/credential-rotation idempotence, unsupported/oversized/bounded rotating work, full pool availability during retrieval, held generation/session/lease changes, actual post-lock waits past expiry and physical-close admission. POP/MIME tests use injected socket/resolver peers and service tests inject only internal transports; no real DNS, mailbox, Akismet or SMTP is contacted. All fixtures use the mandatory disposable database runner and local outbox.

Browser UI and the legacy anonymous`wp-mail.php` trigger are not implemented in this backend batch. Arbitrary ports, STLS/APOP/SASL, non-ASCII POP credentials, attachment ingestion and other MIME multipart types remain explicit unsupported boundaries. Normal archives intentionally do not transfer destination-local mailbox credentials, receipts or polling configuration.

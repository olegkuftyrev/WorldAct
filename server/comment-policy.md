# Human comment approval identity

This fixed Node policy follows the supplied `wp-includes/comment.php` previous-approval lookup (`check_comment`, around lines133–159) and authenticated approval (`wp_check_comment_data`, around lines1352–1394). The source is read-only reference data; no PHP, MySQL or third-party plugin code executes.

Previous approval requires both a nonempty human name and email. A registered email resolves to that actual account's approved **human** `user_id` history. Account email/name updates therefore retain its history, while a new registration cannot inherit earlier unrelated guest history. An unregistered email uses stored author name plus normalized email together. Pending, spam, trash and typed ping rows do not establish approved human history. Empty submitted names are tested before the display fallback to `Anonymous`.

Source history and authentication are separate. A guest supplying a registered address may satisfy that account's source history lookup, but remains a guest with no `user_id`, account authority or moderation privileges. Public inputs cannot supply an actor, role, post author or comment type. Public comment DTOs do not expose stored email or private aliases.

An actually authenticated current post author or global moderator (administrator/editor) receives approval before ordinary manual moderation, keyword, link and disallowed-list rules. Foreign authors and subscribers continue through ordinary policy. This source approval remains subject to the actual Spam Shield plugin and the separate later Akismet filtering contract. An unverified configured Akismet connector can still hold an otherwise trusted approval without contacting the service. Pings receive neither trusted-human approval nor human prior-approval history.

Admission locks the current actor row **FOR SHARE**, then the comment hierarchy, then the actual post **FOR SHARE**. The actor's current display name/email/role/profile and the protected post's actual `author_id` establish the decision. Ordinary metadata updates conflict with the actor share lock; a request that first waits for such an update reads its committed current values. After actor/hierarchy/post waits, `assertActiveAccountAuthentication` revalidates the real session with wall-clock expiry or the real application-password row before granting authenticated approval. A deleted actor or a sign-in revoked/expired during a wait is rejected before rows, remembered-author tokens and notification mail.

The hierarchy lock continues to serialize duplicate admission before filtering and side effects. Existing ownership, access, threading and closed/protected-post checks remain in force. No generalized authentication, shortcode, ping verification or plugin system is introduced.

Guarded real HTTP regressions are split across `comment-approval-history`, `comment-approval-actors` and `comment-approval-waits` test files to respect the existing20/hour admission cap. They cover exact/empty/changed guest identities, actual admin account-email updates, user-ID history, privilege boundaries, real plugin outcomes and real PostgreSQL waits. Waiting cases commit actor demotion/name/email/profile changes, change actual post ownership, log out a real session, let a session expire after its transaction began, revoke a real application password and delete an actor. Source/compiled companion gates retain duplicate, privacy, access, notification and incoming-ping coverage. External services remain suppressed or use the existing controlled transport fixtures.

# Native Image mutations while editing source

The supplied Gutenberg Image hook (`image/use-open-image-media-editor-modal`) owns each opening's `onUpdate`/`onUndo` callbacks and its changed-key Undo attributes. Those genuine callbacks remain unchanged. The source Image callback is not substituted with the current selection or another modal's callback.

`NativeDocumentBridge` reads the real block-editor registry below the existing native provider. A completed opening snapshots that registry around its source callback, retaining the unique changed Image's client ID and resulting attributes. Its source snackbar later invokes the same opening's genuine Undo. Ordinary provider emits are suppressed during that synchronous native callback; only its observed Image field differences enter the document adapter. Closed notices retain their opening's owner, including after another modal opens. Retired sessions cannot publish.

Code input retains existing Image client IDs when matching is unambiguous. Unique exact peers match first, then a single remaining ID/URL peer can retain its owner, so a moved/nested Image or newly authored caption remains attached to its pending operation. Indistinguishable duplicates, newly duplicated owners, deletion and attachment/URL replacement do not acquire someone else's callback. Other native parser recovery fields and rich attribute objects remain intact.

The adapter conditionally rebases `id`, `url`, `sizeSlug`, `href`, `alt` and `caption` against the completed operation's baseline. Newer authored values win; derived links also require unchanged `linkDestination` ownership. It uses the supplied default parser's delimiter grammar for raw offsets and `htmlparser2` source positions for the affected Image tags. It splices only changed fields, preserving unrelated source bytes, quote/spacing choices and invalid/unknown neighbors. The affected Image alone is reparsed and validated by the registered native parser, preserving rich original HTML. No whole-document serialization is caused by a media callback. Ambiguous or invalid targets are left unchanged.

A successful rebase becomes an ordinary document history level with the existing canonical raw source and current footnotes. A rejected/no-op callback reconciles the existing controlled native value without replacing the provider, document/reset key or canonical history. Existing source-mode suppression still rejects arbitrary background canvas events. Native per-opening media-editor/core-data/notices isolation, source block hooks and post/recovery ownership are unchanged.

`tests/native-media-code-rebase.test.ts` exercises raw media splices, native parsing/validity, moved/nested ownership, same-attachment peers, ambiguity/deletion/replacement, custom href/size/caption/alt, changed link ownership and history. Real native browser Save/Code/Undo proofs are recorded in the separate implementation handoff. Independent native review remains required.

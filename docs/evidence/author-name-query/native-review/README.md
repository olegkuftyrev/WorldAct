## Search classification and preserved original observations

The supplied WordPress Search block uses a global home action and the `s` field. It inherits no ambient archive filters when its query attribute is empty. The earlier internal plan incorrectly promised filter preservation for every search form. That planning promise is not the user's instruction and yields to supplied source behavior. See the root's [source decision](../search-source-decision.md), SHA256 `16f4e70c844e3bd1efdfecf0a36b58d5e744c1d46c599f432f37ba97fb6b7b01`, and the machine [classification](source-policy-classification.json).

The three original expectation receipts and their five PNGs remain in [history](history/), with original hashes preserved. Labels such as “lost intersection” describe the initial expectation and were not rewritten. They demonstrate correct global Search behavior, not a WordPress runtime or private-data disclosure bug. No production fix followed them. The final six normal-browser global Search scenes and two genuine no-JS scenes use the corrected source expectation. WorldAct's separate existing local Classic archive form still retains its filters.

**Explicit Search block `attributes.query` is a separate future fidelity gap in this renderer. It is unsupported and is not certified by this package.** No claim is made that native Search preserves ambient author, taxonomy, date or counter parameters.

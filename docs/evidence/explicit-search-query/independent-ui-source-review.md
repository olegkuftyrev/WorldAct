# Explicit Search form shadowing: independent UI source review

Reviewed UI-only commit `9928f5dfc7fbd4af3c0a639ddb2c2f9312d061d2` against backend certificate commit `5a819ef4a68b3dcd8f9c2ea0e033d690f34d029a`. No actionable source finding remains in this bounded diff. This review did not run browser controls, tests, services, or databases.

The full change is one file, `src/public/PublicDocumentController.tsx`, with five additions and four removals. Four instance-method calls in the delegated submit listener now call `Element.prototype.closest`, `matches` (twice), and `getAttribute` with the actual form as receiver. The unchanged `HTMLFormElement` check precedes those calls. Literal explicit query fields can shadow those instance property names; the prototype calls bypass that named-property lookup while retaining the same DOM receiver and selectors.

The initial `event.defaultPrevented` guard, public-island boundary, password/comment selectors, literal logout action test, handler ordering, and all three `preventDefault()` positions are unchanged. Search still falls through to native form submission without cancellation. No fields are dropped or rewritten, no ambient query context is added, and no arbitrary submitted field gains application authority. The existing root-local listener registration/cleanup, captured owner, route/lifecycle freshness checks, mutation guards, and asynchronous handlers are unchanged. The patch adds no await, global listener, ownership bypass, or new form classification.

I read the complete immutable actual-before proof `explicit-search-native-shadows-flushed-proof.json`, SHA-256 `aac1aa475b678843fd9ac859bb265d9ed0c2037fe57d38a471cd70ae79010c7c`. On the original 5a build it records three Classic, 1440px, scripts-enabled real forms whose `closest`, `matches`, or `getAttribute` property is an object supplied by the corresponding hidden field. Each produces the matching product TypeError. All three actual native GETs still reach HTTP 200 with the hidden value and search term intact. Thus the demonstrated defect is an uncaught client exception, not a failed GET or a privacy leak. The fix directly replaces every vulnerable method lookup on that listener path.

Programmatic comparison confirms all `server/`, `shared/`, `scripts/`, package manifests, and the rest of the repository are identical between 5a and 9928 except this controller file. The independent backend certificate remains exactly historical 5a: six files, 31 passes in source mode and 31 passes with the actual compiled API, zero failures/skips; Node bundle SHA-256 `af2177df906780e5c6f65554a1181d606cd337789d3cfa9d9bb8d87ffaf5fc33`.

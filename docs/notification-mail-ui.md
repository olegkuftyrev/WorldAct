# Incoming notifications and Post via email

This React UI implements the supplied source Discussion default controls, Comments type filtering and Writing mailbox fields over the existing reviewed Node/PostgreSQL services. It runs no PHP or MySQL. The settings retain the application's supplied admin typography, source form-table layout, color scheme, menus and responsive rules.

Discussion shows the source outgoing notification, incoming notification and human comment defaults in order. Changes apply only to new posts; pages retain closed incoming notifications and existing per-post flags remain unchanged. The UI states the actual production-only receiver boundary and offers no test transmission.

Comments provides All comment types / Comments / Pings plus Filter. Pings combines pingback and trackback; available choices use independently scoped `typeCounts`. Committing a filter resets pagination, selection and the editor, while links, search, sorting, pagination and moderation retain the committed type. Fixed notification type labels remain visible in rows and edit forms. Typed records have no email field or account identity. Existing backend moderator Reply permissions are preserved. Both source public templates and the legacy React public tree omit notification Reply controls while normal human comments retain threading. Empty Spam/Trash retains its existing all-type scope and explains that scope before deletion.

Writing adds the real private mailbox configuration separately from ordinary site settings: **Save Mail Settings** stores only changed mailbox fields using the last loaded version; **Save Changes** continues to save the other Writing settings. Port 995 selects certificate-verified implicit TLS and port 110 plaintext POP3. Blank passwords retain the stored secret; explicit clearing disables enabled and automatic checks. A deleted category is shown as unavailable with the actual default-category import fallback.

**Check mail now** uses the saved enabled configuration, with no unsaved changes, active check or unexpired five-minute throttle. Automatic checks are suppressed outside production; explicit manual checks can connect in local environments. Results distinguish examined/imported/skipped/duplicate counts and deletion requested versus deletion committed. No unsupported attachment, port, authentication or anonymous-trigger control is offered.

Each mailbox opening owns its requests. A late save preserves newer input and focus; a dismissed opening or changed account cannot receive an old result. Background check status does not silently adopt another administrator's newer configuration version. A stale save therefore receives the real409. Explicit status refresh loads untouched fields from the latest settings while preserving changed input, and a subsequent save sends only those changed fields. Source human and typed comment edit requests also lose ownership when their editor is dismissed.
